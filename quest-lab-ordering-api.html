How to order Quest labs through an API

To order Quest Diagnostics tests from your own software you need three things: a programmatic connection to Quest, a licensed ordering provider with an active NPI, and a HIPAA-compliant place for the patient record. LabLink provides the connection and the patient record through one REST API, on a Quest interface that is already live.

With LabLink you create a patient, pick tests from Quest's catalog, submit a requisition with the ordering provider and bill type, follow its status, and receive signed webhooks when Quest receives the order and when results are posted. This guide walks through each step and what to plan for.

Before you write code

Most teams discover at least one of these late. None of them block building in sandbox; all of them are needed before your first real order.

  • An ordering provider with an NPI. Every order is placed under a licensed ordering provider with an active NPI. Your own clinician or a telehealth partner both work. CareGap does not originate lab orders.
  • A Quest relationship. Bring your existing Quest account, or have LabLink set up a Quest subaccount for you. See ordering without your own Quest account.
  • A signed Platform Agreement and BAA. Results are protected health information, so the BAA is signed before go-live.
  • A decision on who pays. Each order carries a bill type, and insurance orders need extra data. See the bill type table below.

The order lifecycle

  1. Create or look up the patient. An order cannot exist without a patient, and the patient record lives on LabLink's HIPAA-compliant infrastructure. Send your own externalId with each patient so a retried request finds the existing record instead of creating a duplicate. Patient records are billed per patient per year, so duplicates cost money as well as causing confusion.
  2. Pick tests from the catalog. Search the Quest test catalog by name or order code. Some tests have ask-at-order-entry questions that must be answered on the order; read them from the catalog so your intake can collect the answers.
  3. Submit the requisition. Patient, tests, ordering provider, bill type and question answers go in one request. CareGap completes the questionnaire and provider authorization steps.
  4. Follow the requisition's status. Each requisition reports its progress step by step. If something is still needed, the status includes actionRequired with the call that completes it, so your app can prompt the right person instead of failing silently.
  5. Receive webhooks. LabLink sends signed events when Quest receives the requisition and when results are posted. Verify the signature before acting on an event.
  6. Read and store the results. Results come back as structured data. Treat them as protected health information everywhere they go in your system, including logs.

Exact routes, request and response bodies, base URLs and the authentication header are in the API docs and the OpenAPI spec. The playground in the LabLink console sends every call in sandbox and shows the exact request your integration would send.

Implementation notes

  • Make patient creation idempotent with externalId, and look patients up before creating them.
  • Handle errors in one place: every endpoint returns the same error shape.
  • Drive your UI from actionRequired rather than hard-coding the steps an order goes through.
  • Verify webhook signatures, and keep sandbox and production webhook endpoints and secrets separate.
  • Keep API keys server side. Never put them in a browser or mobile app bundle.
  • Keep patient data and results out of application logs, analytics and error trackers.
  • If you client bill and re-bill patients, have counsel review state direct-bill, anti-markup and disclosure rules before you publish prices.

What LabLink does not do

  • Originate lab orders. Your licensed ordering provider authorizes every order.
  • Sell, bill or collect for laboratory testing. Quest bills according to the bill type.
  • Interpret results. Clinical follow-up stays with your ordering provider.

Questions

Do I have to handle HL7 to order Quest labs through LabLink?

No. LabLink runs a live Quest interface with HL7 and file handling already in place. Your application calls a REST API.

Can I test without real patients?

Yes. The LabLink sandbox has its own base URL, keys and webhooks. Use synthetic patient data only in sandbox.

How long until I can place a real order?

Sandbox access does not wait on Quest paperwork. Production typically takes several business days, because Quest subaccount setup is a manual process on Quest's side, and requires a signed Platform Agreement and BAA, a verified ordering provider and a passed certification round trip.

What format are results in?

Results come back as structured data through the LabLink API, and LabLink exposes data through a FHIR layer. Field-level formats are documented in the API docs and OpenAPI spec.
